# Local operational tool contracts

Developer reference; no private records belong here. Runtime tool schemas are in `support/model-tools.ts`; handlers are in `registry.ts`, `operational-tools.ts` and `orchestrator.ts` under `supabase/functions/trax-support/`.

All tool input objects reject extra properties. Tenant/user/role and the Supabase client are never tool arguments. The authenticated handler supplies them server-side and checks for permission changes before and after each invocation. Unknown tool names are rejected, including inherited object names. Entity references received from the page, model or prior conversation are revalidated. No unrestricted database, SQL, shell, RPC or HTTP tool exists.

Operational envelopes contain `status` (`verified`, `partial`, `restricted`, `missing`, `error`, `needs_input`), `observedAt` (ISO timestamp at check start), `findings` (`code`, `summary`, `sourceIds`, `blocking`), `sources`, `navigation`, `checks` and `limitations`. Source IDs refer only to returned records or the scoped availability check, never model-created citations. A verified envelope certifies the stated checks at that observation; it does not certify booking success. Truncated, invalid, restricted or failed coverage is never a complete availability result. Exact inaccessible/missing IDs intentionally share an error to prevent enumeration; an authorized scoped search can return no matches.

Data sources are fixed allowlisted projections in `operational-reads.ts`: vehicles, rentals, rental_key_handovers, blocked_dates, tenant availability settings and pickup_locations ownership. No join reaches customer details or payments. SQL filter builders and pure predicates are generated from the same V2 source used by fleet listing/date selection/checkout precheck. See `workflows/vehicle-availability.md` for channel differences and nullable flag semantics.

## Freshness, failures and budgets

Live tools fetch on every invocation. No shared tenant cache or record snapshots are used. Check Again takes the previous diagnostic from the authenticated encrypted context, revalidates its vehicle and reruns it. Conversation turns never establish live facts. Multiple database reads are not an atomic snapshot or lock; a concurrent booking can still change the outcome.

Each upstream database request has an eight-second timeout; model calls have an 18-second timeout within a 65-second conversation deadline. There are at most eight model calls and seven tool invocations, one model-requested tool per turn. Responses calls have a 2,400 output-token cap, 48,000-character input-context cap and 24 KB response cap. There are no automatic retries; a user can deliberately check again. Auth/read service errors are sanitized. Server logging is counters/status/time only, without prompt, record IDs, secret values or response bodies.

Additional fleet/issue tool contracts and the separate user-click ticket API are documented in [support-escalation.md](support-escalation.md). There is no model tool to submit or update a ticket. Only the authenticated UI submission exception and authorized staff management endpoints can write TRAX support records.

Final model source IDs must exist in the current request's result set, and navigation IDs must resolve through the approved registry. Unknown references/URLs fail to labelled prepared guidance. The UI disables model-generated hyperlinks/images and always shows the canonical diagnostic findings and coverage limits. These controls constrain authority and evidence references; real-model answer quality still requires live evaluation. They are not a claim that language-model hallucinations are impossible.

## Deliberately unavailable

No customer-support context, business writes, rental-state transitions, handover completion, record repair, charts, exports, voice or feedback-driven code/knowledge publication. Persistent support tickets require the reviewed storage migration and explicit support configuration before activation. The three additional read-only finance tool contracts, default-disabled grants and restricted Stripe adapter are documented in [read-only-finance.md](read-only-finance.md). An OpenAI key alone does not enable them; full rental financial totals remain unsupported without historical currency provenance.
